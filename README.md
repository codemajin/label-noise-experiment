# label-noise-experiment

English | [日本語](README_ja.md)

Experiments on combining cleanlab (Confident Learning) with biquality-learn **without any human verification**.
The results are written up as a paper (English: `latex/main.pdf`, Japanese: `latex/main_ja.pdf`).

## Running

```sh
uv sync
uv run python -m label_noise_experiment.run --model lr    # about 6 min (24 cores)
uv run python -m label_noise_experiment.run --model hgb   # about 60 min
uv run python -m label_noise_experiment.summarize         # writes results/summary.md and the figure

# Additional experiments for the paper, and export of tables and figures
# (all experiments including run can be executed with sh rerun_all.sh; about 3 hours in total)
for m in lr hgb; do
  uv run python -m label_noise_experiment.oracle_check --model $m --oracle-frac 0.1
  uv run python -m label_noise_experiment.oracle_check --model $m --oracle-frac 0.3
  uv run python -m label_noise_experiment.mechanism --model $m
done
uv run python -m label_noise_experiment.hgb_lr_check      # check the HGB learning rate without test data
uv run python -m label_noise_experiment.export_latex      # tables (en/ja), figure, number macros (latex/numbers.tex)
wsl sh latex/build.sh                                      # build main.pdf and main_ja.pdf with Docker in WSL (texlive/texlive)
```

biquality-learn 0.1.0 does not work with scikit-learn 1.6 or later (`_validate_data` was removed), so scikit-learn is pinned to `<1.6`.

## Setup

| Item | Details |
|---|---|
| Datasets | digits (1,797 samples, 10 classes), synth (make_classification, 8,000 samples, 6 classes), covtype (stratified subsample of 12,000, 7 classes) |
| Noise | symmetric (to a uniformly random other class), pair (to a fixed other class per class), instance (samples that a model trained on clean labels finds ambiguous are more likely to be flipped, to that model's runner-up class). Noise rates 20% / 40% |
| Split | 70% train / 30% test. Noise only on the training side; test labels stay clean |
| Base models | LogisticRegression (lr), HistGradientBoosting (hgb, learning_rate=0.05) |
| Repetitions | 5 seeds; 2 models × 90 conditions |
| cleanlab | Out-of-sample `pred_probs` from 5-fold CV are passed to `find_label_issues` and `get_label_quality_scores` |

The HGB learning rate of 0.05 was originally chosen by looking at accuracy on the test data of seed 0. Cross-validation within the training data, without test data (`hgb_lr_check`), leads to the same choice (on covtype, 76.1% at 0.1 vs. 79.1% at 0.05).

## Methods compared

| # | Method | Description |
|---|---|---|
| 1 | `baseline` | Train on the noisy labels as they are |
| 2 | `cl_prune` | Remove the samples flagged by cleanlab and retrain with uniform weights |
| 2 | `cl_cleanlearning` | cleanlab's standard `CleanLearning`. Removes the same samples as `cl_prune` and retrains with class weights 1 / (diagonal of the estimated noise matrix) |
| 3 | `bq/<split>/<algo>` | Build pseudo trusted/untrusted sets from cleanlab's output and train with biquality-learn |
| 4 | `cl_weight/*` | Use the label quality score (self_confidence / normalized_margin) as sample weights |
| 4 | `cl_feature` | Add the label quality score as a feature and feed score = 1 (most reliable) at inference |
| ref | `oracle_clean` | Train on clean labels (upper bound) |
| ref | `oracle_trusted{10,30}/irbl` | Assume a random 10% / 30% was fixed by hand and use it as trusted (the intended use of biquality-learn) |

How the pseudo trusted set is built (`split`):

- `naive`: all unflagged samples are trusted, flagged ones untrusted
- `topconf`: among unflagged samples, the top 30% by quality score per class are trusted, all the rest untrusted
- `random`: among unflagged samples, a random 30% per class are trusted, all the rest untrusted

biquality-learn algorithms (`algo`): IRBL, K-PDR, K-KMM (weighting methods); GLC (LossCorrection), Plugin, IRLNL (transition-matrix methods, with the matrix estimated from the trusted set by `gold`); trusted_only.

## Findings

1. **`bq/naive/irbl` is the best method without human input, but its gap to `cl_prune` is small.** The paired difference is +0.45±0.36 pt for lr (wins in 64% of conditions) and +0.31±0.24 pt for hgb (wins in 71%), at about three times the training time. cleanlab's standard `CleanLearning` (with per-class reweighting) did not beat `cl_prune` (lr −0.75 pt, hgb −0.06 pt). Part of the advantage of `naive` comes from its large trusted set (53–85% of the training data).
2. **Transition-matrix methods (GLC / Plugin / IRLNL) break down badly with pseudo trusted sets.** The trusted labels are the noisy labels themselves and the noise concentrates in the untrusted set (39–92% of naive untrusted labels are wrong), so the transition matrix is estimated far from reality. Even in the control experiment where a random 10% gets genuinely clean labels (`oracle_check`), however, these methods fell below the baseline (GLC: lr −2.62 / hgb −11.78 pt). The accurate interpretation is that methods already weak in this setting break down much further with pseudo trusted sets. According to `mechanism`, GLC underestimates the diagonal of the transition matrix even with genuine trusted data (lr 0.50 and hgb 0.62 vs. a clean rate of 0.70 in the untrusted set).
3. **`topconf`, which picks the most confident samples as trusted, is worse than `naive` and `random`.** The concern that the trusted set becomes biased toward "easy samples" (selection bias) shows up in the numbers, especially on covtype.
4. **Using the score as weights is on par with cl_prune for lr and worse for hgb** (−1.26 pt).
5. **Using the score as a feature depends on the model.** It worked as well as cl_prune for hgb but degraded lr badly: a linear model cannot express interactions between the score and the other features, so the score can only shift each class's intercept.
6. **Under instance noise (closer to real annotation errors), every automatic method gains little.** cleanlab's recall is only 37–74%. Under pair noise at 40%, fixing just 10% by hand gains about +20 pt, while the automatic methods gain about +7 pt.
7. **With the trusted-set size matched, the advantage of human verification is clear.** IRBL with 30% fixed by hand beat `bq/naive/irbl` by +3.91 pt for lr (win rate 72%) and +5.00 pt for hgb (win rate 92%). With 10% it wins on average but in fewer than half of the conditions.
